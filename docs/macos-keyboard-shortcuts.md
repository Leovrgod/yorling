# macOS 截图快捷键与偶发按键延迟排查（0.1.4）

## 现场结果与边界

用户反馈实体键盘上的 Win+Shift+S、Win/Command+Shift+4 均无反应，并有偶发需要重复按键的感觉。现场 0.1.3 安装版仍正常运行；在该安装版上用程序发送两组组合键，都能启动系统截屏，随后用 Esc 取消。因此不能简单认定截图映射完全失效，也不能从合成输入测试推断实体键盘一定正常。

系统识别键盘为通过 USB 接收器连接的 2.4G 无线键盘，未提供电量字段。没有找到该键盘的系统修饰键交换配置；慢速键、粘滞键处于关闭状态。没有捕获到用户实际操作那两组组合键的物理输入样本，尚不能确认 Win 键锁定、键盘模式、电量、无线丢包或其他输入工具是否参与了问题。缺少电量数据不代表电量充足或不足。

## 可确认的问题与修复

### 映射事件重新进入全局队列，可能改变事件顺序

原来在 CGEventTap 回调中调用 `CGEventPost`，将新事件放回 HID 入口，同时吞掉原事件。对安装版发送一组受控的快速截图按下/松开，并在末尾发送修饰键松开标记，末端拦截器记录到：

```text
映射后的 4 按下
修饰键松开
映射后的 4 松开
```

原始发送顺序是字母按下、字母松开、修饰键松开。重新投递会经过上游监听器，也允许已经排队的后续事件先于重发事件处理。它能解释某些快捷键的时序异常，但单次复现不能证明所有主观延迟都来自这里。[Apple：CGEvent.post](https://developer.apple.com/documentation/coregraphics/cgevent/post(tap:))

修复后，单个映射事件作为当前回调的替代事件直接返回；序列的前缀通过 `CGEventTapPostEvent` 投递到当前监听器之后，最后一个事件由回调返回。这样保留输入顺序，并避免回到 HID 入口。键盘触发的鼠标点击和滚轮也使用当前回调的投递点；独立的鼠标移动线程维持原来的显示时钟实现。[Apple：回调返回值与所有权](https://developer.apple.com/documentation/coregraphics/cgeventtapcallback)、[Apple：tapPostEvent](https://developer.apple.com/documentation/coregraphics/cgevent/tappostevent(_:))

### 自动重复字段编号错误

原代码将 `kCGKeyboardEventAutorepeat` 写成 11。Apple SDK 的 `CGEventTypes.h` 中该字段为 **8**；11 是滚轮第一轴的增量。真实 CoreGraphics 事件测试暴露了这个错误。它让系统自动重复事件不能被正确识别，影响截图、复制/粘贴等需要抑制重复触发的快捷键和鼠标模式。

修复字段编号，并在返回单个映射事件时保留原事件时间戳和自动重复标志。测试验证长按截图组合会被抑制，普通映射仍能保留自动重复信息。

### 监听中断、停用后残留按键状态

之前监听中断只清理鼠标模式；待定的 Space 导航层、括号模式和快捷键状态可能继续保留。停用引擎时，Ctrl→Cmd 与截图映射也没有配对释放全部目标键。针对“同时持有两个映射快捷键后停用”的回归测试在旧实现失败：应返回两个松键事件，实际返回零个。

现在统一清理输入状态：配对释放导航层、重放键、Ctrl→Cmd 和截图目标键，清空各临时模式，并保留配置与启用偏好。Ctrl→Cmd 记录触发时的修饰标志，以便正确补发松键。回调中断时同时取消相关浮层；仅供音乐使用或临时关闭映射的监听也能重新启用。系统事件投递移到引擎锁外，每次原生回调使用 autorelease pool。

这不是对所有无线丢键情况的自动检测；未发生监听中断的硬件丢键仍需单独对照。

## 验证

- `cargo test --workspace --locked`：280 项通过；显示时钟的桌面专用测试仍默认跳过。
- `pnpm test`：181 项通过；TypeScript/Vite 生产构建、macOS release 应用打包通过。
- 覆盖截图快捷键配对松键、原生截图组合透传、Windows 原生组合不被接管、重复事件、单事件替换、序列顺序、时间戳/标志、监听中断及模式清理。
- 0.1.4 已签名并替换本机安装版；签名验证、版本、运行路径及可执行文件哈希校验通过，旧版已备份。
- 在实际 0.1.4 安装版上重复快速按键探针，结果变为：`4 按下 → 4 松开 → 修饰键松开`。
- 实际安装版上程序触发 Win/Command+Shift+S、Win/Command+Shift+4，均能启动系统截屏并取消。受控鼠标动作探针验证左右点击事件按下/松开成对到达，上下滚轮事件也能到达；探针在到达应用前拦截测试动作。

程序触发的验证覆盖应用和系统输入链路，不包含无线传输和键盘硬件。后续优先使用实体键盘复测；若仍只有实体组合无效，可对照有线连接或充电后的表现，并确认该键盘的 Win 键锁定/系统模式。不要在缺少物理输入证据时将原因归结为电量，也不要宣称本轮修复已排除所有延迟。
