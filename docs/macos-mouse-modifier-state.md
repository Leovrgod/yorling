# macOS 键盘鼠标与修饰键状态排查

## 现象与可复现机制

用户反馈键盘鼠标模式中，N 偶尔看起来像右键、U/O 滚动失效，Dock 图标也会突然在鼠标经过时放大。Dock 的图标放大是当前 macOS 仍有的功能；本机默认没有启用它，但 Control+Shift 可临时反转该设置。

在 macOS 27.2 上，用受控测试先向系统注入一个带有过期 Control+Shift 标志的鼠标事件，然后发送无修饰键的 Tab/J/N/U 事件。原安装版的结果：

- Dock 图标的最大宽度从 71 增至约 130 像素。
- Yorling 随后的鼠标移动、N 左键按下/松开和 U 滚轮事件都继承了 Control+Shift。
- 即使键盘事件本身不带这两个标志，鼠标移动仍持续把继承到的标志写回系统。Control+左键可被应用解释为右键，这与此前日志中「N 确实生成左键」并不矛盾。

另一个测试先进入鼠标模式，再注入过期修饰键状态，并让后续键盘事件也报告同样的过期标志；原安装版同样延续了异常状态。上述测试使用合成事件受控播种，**没有捕获用户实际使用中最初是谁或什么时序引入了错误状态**，不能据此断言是 Tab、键盘硬件或其他应用首次触发。

## 修复

- 键盘鼠标事件显式设置修饰键标志，不再默认继承合成事件源的全局状态。鼠标模式要求无 Control/Shift/Option/Command 的 Tab 进入，实际修饰键变化会按现有行为退出该模式；因此从进入时保存输入标志，整次模式沿用该快照，避免后续被污染的鼠标层按键继续传播错误标志。Caps Lock 等其余标志仍保留。
- 移动线程、左/右/后退键、拖动释放和滚轮共用同一规则。真实实体鼠标事件不由这个规则改写。
- 括号模式仅吞掉自己消费过按下事件的按键释放；之前在进入模式前已按下的修饰键或普通键，其释放事件必须透传。此前受控测试中 Control/Shift 按下各到达一次、松开各到达零次；修复后均为一次按下、一次松开。
- 自定义 Option+Tab 切窗提交时，将原始 Option 松开事件继续传给系统，同时完成切窗，避免原先只执行切窗而吞掉松开事件。

## 验证范围

在独立运行的修复版事件监听器上重复以上两种播种测试：鼠标移动、N 左键和 U 滚轮输出不再携带额外 Control/Shift，Dock 图标恢复至 71 像素。测试拦截模拟点击和滚轮，结束时恢复光标位置与系统标志。测试覆盖事件通路和 Dock 的实际表现，不包含无线键盘的物理传输，也不证明所有外部程序生成的异常输入均可被识别。

修复版覆盖安装后，从 `/Volumes/torser/Applications/Yorling.app` 运行并重复两种播种测试和括号修饰键配对测试，结果一致；签名、运行路径、Finder Sync 注册及安装版与构建版的可执行文件哈希均已核验。Rust 工作区测试 314 项通过、1 项桌面专用测试跳过，前端测试 182 项通过。旧安装版保存在被忽略的 `target/local-install-backups/` 目录中；应用版本号保持 0.1.4。
